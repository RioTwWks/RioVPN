> на моём сервере установлен 3x-ui, который перенаправляет трафик на другой сервер через outbound. я хочу запускать свой телеграм бот на сервере с 3x-ui. как мне направить трафик тг-бота так же, как это делает 3x-ui?

Раз у тебя уже настроен `3x-ui` и есть рабочий `outbound` (например, для обхода блокировок или цепочки прокси), то логичнее всего использовать тот же самый процесс Xray, который уже запущен панелью. Тебе нужно создать точку входа (local inbound) в этот процесс и направить трафик через нужный `outbound`.

Вот пошаговый план, как это сделать через интерфейс 3x-ui, чтобы не ломать основную конфигурацию.

### 1. Создание локального Inbound в 3x-ui

Тебе нужно добавить новый входящий поток, который будет слушать только локальный интерфейс.

1.  Зайди в панель **3x-ui**.
2.  Перейди в раздел **Inbounds** (Входящие).
3.  Нажми **Add Inbound** (Добавить).
4.  Заполни параметры:
    *   **Protocol**: `socks` (рекомендую) или `http`.
    *   **Listen**: `127.0.0.1` (критично, чтобы не светить порт наружу).
    *   **Port**: любой свободный, например `10808`.
    *   **Auth**: можно оставить пустым (так как слушаем localhost) или задать user/pass для надежности.
    *   **Tag**: задай понятный тег, например `local-bot-proxy`.
5.  Сохрани.

### 2. Настройка Routing (Маршрутизации)

Самый важный шаг. По умолчанию Xray может отправлять трафик напрямую (`direct`). Тебе нужно явно указать, что трафик с нового локального порта должен уходить через твой рабочий `outbound`.

1.  Перейди в раздел **Routing** (Маршрутизация) в меню 3x-ui.
2.  Добавь новое правило (**Add Rule**).
3.  Настрой правило:
    *   **Inbound Tag**: выбери тег, который ты создал на шаге 1 (`local-bot-proxy`).
    *   **Outbound Tag**: выбери тот тег, который используется для твоего туннеля на другой сервер (например, `proxy`, `vless-out` или как он у тебя назван).
    *   **Domain/IP**: можно оставить пустым (все трафик с этого inbound) или указать `geosite:telegram`, если хочешь маршрутизировать только ТГ.
4.  Убедись, что это правило стоит **выше** правил, которые отправляют трафик в `direct`.
5.  Сохрани конфигурацию и примени изменения (панель обычно перезапускает Xray).

### 3. Подключение бота (aiogram)

Теперь твой Xray слушает `127.0.0.1:10808` и форсит трафик в нужный туннель.

```python
from aiogram import Bot, Dispatcher
from aiogram.client.session.aiohttp import AiohttpSession

async def main():
    # Используем SOCKS5, так как мы настроили socks inbound
    # Если настроил http - используй http://127.0.0.1:10808
    proxy_url = "socks5://127.0.0.1:10809" 
    
    # Если в 3x-ui задавал логин/пароль для socks:
    # proxy_url = "socks5://user:pass@127.0.0.1:10808"

    session = AiohttpSession(proxy=proxy_url)
    bot = Bot(token="YOUR_TOKEN", session=session)
    dp = Dispatcher()
    
    # ... остальной код ...
    await dp.start_polling(bot)
```
*Примечание: в примере выше опечатка в порту (10809), исправь на свой (10808).*

### 4. DevOps-нюансы для 3x-ui

1.  **Перезапись конфига:** 3x-ui хранит конфигурацию в своей БД и генерирует `config.json` при каждом изменении или рестарте. **Не редактируй `config.json` вручную**, иначе панель затрет изменения. Все делай через UI панели.
2.  **Firewall (UFW/iptables):** Убедись, что порт локального прокси (10808) не проброшен наружу. `listen: 127.0.0.1` должно защищать, но проверка лишней не будет:
    ```bash
    ss -tlnp | grep 10808
    # Должно быть 127.0.0.1:10808, а не 0.0.0.0:10808
    ```
3.  **Альтернатива (если 3x-ui ограничивает):**
    Если версия 3x-ui не дает гибко настроить routing для конкретного inbound (некоторые старые версии упрощены), проще поднять рядом **отдельный процесс Xray** в режиме клиента.
    *   Скопируй настройки outbound из конфига 3x-ui.
    *   Создай минимальный `client-config.json` с socks inbound и этим outbound.
    *   Запусти как отдельный systemd сервис.
    *   Это изолирует бота от настроек панели, но дублирует процесс.

**Рекомендация:** Попробуй сначала через UI 3x-ui (Inbound + Routing). Это наиболее чистое решение в рамках твоей текущей инфраструктуры.

> Окей, а для тестирования на локальном компьютере как направить трафик до 3x-ui?

У тебя есть два пути: «быстрый» (через SSH-туннель к уже настроенному локальному прокси на сервере) и «классический» (поднятие клиента на локальной машине).

### Способ 1: SSH-туннель (Рекомендую для тестов)

Это самый быстрый способ. Ты используешь тот самый **local inbound** (SOCKS/HTTP), который мы настраивали в предыдущем шаге на сервере (например, `127.0.0.1:10808`). Тебе не нужно настраивать VLESS-клиент на локальном ПК, ты просто пробрасываешь порт.

1.  **Убедись, что на сервере создан Inbound:**
    В 3x-ui должен быть создан inbound, который слушает `127.0.0.1` (как мы обсуждали ранее), и правило Routing, которое отправляет его трафик в нужный `outbound`.

2.  **Подними SSH-туннель с локальной машины:**
    Выполни в терминале локального компьютера:
    ```bash
    ssh -L 10808:127.0.0.1:10808 user@your-server-ip
    ```
    *   `-L 10808:127.0.0.1:10808` — пробрасывает твой локальный порт `10808` на серверный `127.0.0.1:10808`.
    *   Теперь любой трафик на твоем ПК на `127.0.0.1:10808` уйдет на сервер, попадет в процесс Xray (3x-ui) и уйдет через настроенный `outbound`.

3.  **Запуск бота:**
    В коде бота указываешь прокси как обычно:
    ```python
    proxy_url = "socks5://127.0.0.1:10808"
    ```
    *Плюсы:* Не нужно ставить v2rayN/Clash на локальную машину. Трафик идет ровно тем же путем, что и на сервере.
    *Минусы:* Требуется активное SSH-подключение.

---

### Способ 2: Локальный клиент (V2rayN / Clash / Hiddify)

Если ты хочешь тестировать независимость от SSH-сессии или проверить работу публичного inbound.

1.  **Получи ссылку на подключение:**
    В панели 3x-ui экспортируй ссылку (Subscription Link или QR-код) для любого рабочего **публичного** inbound (который слушает `0.0.0.0`).
    *Важно:* Убедись, что этот inbound в Routing правилах тоже отправляет трафик в нужный `outbound` (обычно в 3x-ui это правило `Proxy` или `Global`).

2.  **Настрой клиент на ПК:**
    *   Установи клиент (например, **Hiddify**, **v2rayN** или **Clash Verge**).
    *   Импортируй ссылку.
    *   Включи режим **System Proxy** или узнай порт локального SOCKS/HTTP (обычно `10808`, `10809` или `2080` в настройках клиента).

3.  **Запуск бота:**
    ```python
    # Пример для v2rayN (стандартный порт SOCKS)
    proxy_url = "socks5://127.0.0.1:10808" 
    ```

---

### Способ 3: Переменные окружения (Универсально)

Чтобы не менять код каждый раз при переключении между локальной разработкой и продакшеном, вынеси прокси в `.env`.

**Локальный `.env`:**
```ini
BOT_PROXY=socks5://127.0.0.1:10808
```

**Продакшен `.env` (на сервере):**
```ini
BOT_PROXY=socks5://127.0.0.1:10808
```
*(Здесь работает тот же принцип: на сервере бот стучится в локальный порт 3x-ui, локально — в SSH-туннель или клиент).*

**Код:**
```python
import os
from aiogram import Bot, Dispatcher
from aiogram.client.session.aiohttp import AiohttpSession

async def main():
    proxy_url = os.getenv("BOT_PROXY")
    
    session = AiohttpSession(proxy=proxy_url) if proxy_url else AiohttpSession()
    bot = Bot(token="YOUR_TOKEN", session=session)
    dp = Dispatcher()
    
    await dp.start_polling(bot)
```

### Итог
Для быстрой отладки используй **SSH-туннель (Способ 1)**. Это идеально ложится на твою текущую инфраструктуру с 3x-ui: ты тестируешь именно серверную конфигурацию роутинга, не поднимая лишних сущностей на локалке. Просто держи терминал с SSH открытым во время тестов.

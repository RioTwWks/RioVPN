# **Telegram-бот для продажи VPN-подписок**  
**Спецификация проекта (spec.md)**

## 1. Цели и общее описание

Разработать Telegram-бота, который автоматизирует продажу VPN-подписок двух типов:

- **Тип A (RU)** – подключение к российскому VPS (3x-ui), который обеспечивает обход «белых списков» мобильных операторов (протокол VLESS + Reality + XHTTP).
Нюанс: нужно создавать отдельных пользователей в Hiddify-Manager для каждого клиента (или для каждой группы). Затем в 3x-ui для каждого такого пользователя создавать отдельный outbound с соответствующими параметрами (адрес, порт, uuid). Это нужно для тог8о, чтобы контролировать трафик каждого клиента и использовать встроенные лимиты Hiddify. При необходимости легко заблокировать одного клиента, не затрагивая остальных.
- **Тип B (EU)** – подключение к европейскому VPS (Hiddify-Manager), который выступает транзитным выходом в мировой интернет.

Ключевые требования:

- Каждый клиент получает **отдельного пользователя** в соответствующей панели (для EU — в Hiddify, для RU — в 3x-ui).
- Бот выдаёт готовую vless:// ссылку (или ссылку на подписку) после успешной оплаты.
- Поддержка автоматического продления, отключения при истечении срока или превышении трафика.
- Интеграция с платёжными системами (Cryptomus, YooKassa, Telegram Stars).

## 3. Интеграция с панелями

### 3.1. 3x-ui API

- **Документация**: https://www.postman.com/hsanaei/3x-ui/documentation/q1l5l0u/3x-ui и https://github.com/MHSanaei/3x-ui/wiki/Configuration https://github.com/hiddify/hiddify-manager/wiki/API-Reference
- **Основные эндпоинты**:
  - `GET /panel/api/inbounds/list` – получить список инбаундов и клиентов.
  - `POST /panel/api/inbounds/addClient` – добавить клиента в существующий инбаунд.
  - `POST /panel/api/inbounds/updateClient` – изменить лимиты клиента.
  - `POST /panel/api/inbounds/delClient` – удалить клиента.
  - `GET /panel/api/inbounds/getClientTraffic/:email` – получить использованный трафик.

**Аутентификация**: базовый логин/пароль администратора.

### 3.2. Hiddify-Manager API

- **Документация**: https://hiddify.com/manager/contribution/How-to-use-API-in-HiddifyManager-project https://rio2skadi.pro/aav6Vcx7HYsY6hnk5K2226jQ9ZDS2N/api/openapi.json https://rio2skadi.pro/aav6Vcx7HYsY6hnk5K2226jQ9ZDS2N/api/docs
- **API версии 2**, эндпоинт: `https://<domain>/api/v2/`
- **Аутентификация**: передача заголовка `Hiddify-API-Key: <UUID администратора>`.
- **Основные операции**:
  - `POST /admin/user/` – создать пользователя (параметры: username, expiry_time, data_limit, etc.)
  - `GET /admin/user/<uuid>` – получить информацию о пользователе
  - `PUT /admin/user/<uuid>` – изменить пользователя (обновить лимиты, продлить)
  - `DELETE /admin/user/<uuid>` – удалить пользователя
  - `GET /admin/users/` – список всех пользователей

**Важно**: для каждого покупателя создаётся **отдельный пользователь** в Hiddify. UUID пользователя, полученный от Hiddify, сохраняется в БД бота.

## 4. Структура базы данных

### 4.1. Модели (SQLAlchemy)

```python
class User(Base):
    __tablename__ = 'users'
    id = Column(Integer, primary_key=True)
    telegram_id = Column(BigInteger, unique=True, nullable=False)
    username = Column(String)
    created_at = Column(DateTime, default=datetime.utcnow)

class Subscription(Base):
    __tablename__ = 'subscriptions'
    id = Column(Integer, primary_key=True)
    user_id = Column(ForeignKey('users.id'), nullable=False)
    type = Column(Enum('ru', 'eu', name='sub_type'), nullable=False)
    status = Column(Enum('active', 'expired', 'blocked', name='sub_status'), default='active')
    start_date = Column(DateTime, nullable=False)
    expiry_date = Column(DateTime, nullable=False)
    traffic_limit = Column(BigInteger)  # в байтах, NULL = безлимит
    traffic_used = Column(BigInteger, default=0)
    # Данные для доступа к панелям
    panel_uuid = Column(String(64))          # UUID пользователя в Hiddify (для EU) или email в 3x-ui (для RU)
    inbound_tag = Column(String)             # для 3x-ui
    link = Column(Text)                      # сгенерированная vless:// ссылка
```

### 4.2. Вспомогательные таблицы

- `payments` – логи платежей (сумма, статус, внешний ID)
- `settings` – хранение конфигурации (платёжные ключи, URL панелей, дефолтные лимиты)

## 5. Функциональные требования

### 5.1. Команды бота

- `/start` – приветствие, меню выбора подписки.
- `/buy` – выбор типа подписки (RU / EU) и срока (1 месяц, 3 месяца, 6 месяцев, год).
- `/my` – отображает текущую подписку, статус, использованный трафик.
- `/renew` – продление подписки (открывает платёж).
- `/support` – контакт поддержки.
- `/referral` – реферальная программа.
- **Административные команды** (доступны только владельцу):
  - `/stats` – статистика по продажам, трафику.
  - `/broadcast` – рассылка пользователям.
  - `/suspend <telegram_id>` – приостановить подписку.
  - `/grant <telegram_id> [type] [days]` – выдать подписку вручную.

### 5.2. Сценарий покупки

1. Пользователь выбирает тип и срок.
2. Бот запрашивает подтверждение и формирует платёж.
3. После успешной оплаты:
   - Для RU: через API 3x-ui создаётся клиент в инбаунде (email = `user_<telegram_id>`). Параметры инбаунда (порт, SNI, public key) берутся из настроек бота.
   - Для EU: через API Hiddify создаётся пользователь с expiry date и лимитом трафика.
   - Бот генерирует vless:// ссылку (или ссылку на подписку) и отправляет её пользователю вместе с инструкцией.
4. Запись о подписке сохраняется в БД.

### 5.3. Сценарий продления

- За 3 дня до окончания бот отправляет напоминание с предложением продлить.
- При продлении создаётся новый платёж; после оплаты обновляется `expiry_date` в БД и в соответствующей панели (через API).

### 5.4. Контроль трафика

- Фоновый воркер раз в сутки (или чаще) опрашивает API обеих панелей для получения использованного трафика.
- Если трафик превышает лимит, подписка блокируется (удаляется пользователь из панели или меняется статус на `blocked`).
- Если подписка истекла, аналогично блокируется.

### 5.5. Генерация ссылок

- **Для RU (3x-ui)**: генерируется vless:// ссылка по шаблону:
  ```
  vless://<uuid>@<server>:<port>?encryption=none&flow=xtls-rprx-vision&security=reality&sni=<sni>&fp=chrome&pbk=<public_key>&sid=<short_id>&type=xhttp&path=%2F&mode=auto#<tag>
  ```
  Все параметры берутся из настроек инбаунда (который один для всех RU-клиентов) и UUID созданного клиента.
- **Для EU (Hiddify)**: после создания пользователя Hiddify сам возвращает ссылку (в формате `vless://...` или `hysteria2://...`). Её можно использовать как есть.

## 7. API Telegram-бота (методы)

Бот должен обрабатывать следующие типы взаимодействий:

- **Команды** (`/start`, `/buy`, `/my`, `/renew`, `/support`, `/referral`, `/stats` и т.д.).
- **Inline-клавиатуры** для выбора типа подписки, срока, способа оплаты.
- **Callback-запросы** для обработки нажатий на кнопки.
- **Pre-checkout и success** для Telegram Stars (если используется).
- **Webhook** для приёма уведомлений от платёжных систем (например, Cryptomus callback).

## 8. Безопасность и администрирование

- Все секреты (токены бота, ключи API) хранятся в переменных окружения, а не в коде.
- Доступ к админ-командам ограничен по Telegram ID.
- При работе с 3x-ui используется HTTPS (желательно) и сложный пароль.
- API Hiddify работает через HTTPS, ключ администратора генерируется один раз и хранится в БД бота.
- Логирование всех операций (уровни: INFO, ERROR) с ротацией.

## 9. Примеры использования (user stories)

1. **Покупка RU-подписки**  
   - Пользователь нажимает `/buy`, выбирает "Россия (обход белых списков)", затем срок.  
   - Бот показывает стоимость, кнопку "Оплатить".  
   - После оплаты создаётся клиент в 3x-ui, бот отправляет vless:// ссылку и инструкцию.

2. **Покупка EU-подписки**  
   - Аналогично, но создаётся пользователь в Hiddify, и бот отправляет ссылку, полученную от Hiddify.

3. **Автоматическое отключение при истечении срока**  
   - Воркер каждый час проверяет `expiry_date` и `status`.  
   - Если срок истёк, вызывает API для удаления пользователя из панели, обновляет статус в БД на `expired`.

4. **Продление**  
   - Пользователь нажимает `/renew`, выбирает подписку, оплачивает.  
   - Бот обновляет `expiry_date` в БД и в панели (через API).

## 10. Развёртывание и сопровождение

- **Контейнеризация**: Docker Compose для бота, базы данных, воркера.
- **Миграции**: Alembic для управления схемой БД.

- **Обновления**: бот может быть остановлен на пару секунд для перезапуска без потери данных (stateless).
